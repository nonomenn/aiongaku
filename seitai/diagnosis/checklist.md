# 診断レポートの作り方（1院あたり10〜15分）

事業計画 p.5「診断レポート：その店用に1枚、AIが半自動で作成」の手順書。
**見るのは公開情報だけ**（Googleマップ・ホームページ・LINEの公開ページ）。電話で聞き出したり、院のシステムに入ったりはしない。

## 流れ

1. **点検（人・約10分）**：下の17項目をスマホで見て、`ok / warn / ng / unknown` とメモを付ける
2. **JSON化（AI）**：点検メモを `prompt.md` のプロンプトでClaudeに渡し、入力JSONを作らせる
3. **生成（スクリプト）**：
   ```bash
   python seitai/diagnosis/make_report.py 入力.json
   ```
   → `<院名>_診断レポート.html` ができる。ブラウザで開き「印刷 → PDFに保存」（用紙A4・余白なし・背景のグラフィックON）
4. **最終チェック（人）**：下の「渡す前の確認」を見てから送る

サンプル：`samples/sample_input.json` → `samples/みどり整体院（見本）_診断レポート.pdf`

## 点検17項目

判定の基準：`ok`＝できている／`warn`＝あるが不十分／`ng`＝ない／`unknown`＝外から分からない（面談で聞く）

### Googleマップ（「地域名＋整体」で検索して院を開く）
| ID | 項目 | ok の目安 |
|---|---|---|
| gm_hours | 営業時間・定休日が正しい | HP・ポータルの記載と一致。臨時休業も反映 |
| gm_photos | 写真が十分 | 院が上げた写真10枚以上、1年以内のものがある |
| gm_reply | 口コミに返信 | 直近10件の大半に返信がある |
| gm_website | HPへのリンク | 自院HPにリンク（ポータルなら warn） |
| gm_booking | 予約リンク | 自院の予約手段にリンク（ポータルなら warn） |
| gm_desc | 説明文・メニュー | 特徴・対象・料金のどれかが分かる |

### ホームページ（スマホで開く）
| ID | 項目 | ok の目安 |
|---|---|---|
| hp_exists | 自院のHPがある | ポータルの掲載ページだけなら ng |
| hp_mobile | スマホで読みやすい | 拡大しなくても読める |
| hp_price | 料金が明記 | 初回料金と通常料金が分かる |
| hp_first | 初回の流れ | 所要時間と何をするかが分かる |
| hp_cta | 予約まで1タップ | 電話・LINE・予約ボタンが目立つ所にある |
| hp_fresh | 情報が新しい | お知らせが1年以内、古い営業時間が残っていない |
| hp_ssl | https | アドレスバーに鍵マーク |

### LINE・予約
| ID | 項目 | ok の目安 |
|---|---|---|
| ln_account | LINE公式アカウント | HP・マップ・ポータルのどこかに記載がある |
| ln_link | LINEへの導線 | HP・マップから友だち追加まで迷わず行ける |
| ln_online | 自院のネット予約 | ポータル以外で、24時間ネット予約できる |
| ln_follow | 来店後のフォロー配信 | 外からは分からない → 基本 `unknown`、面談で聞く |

## 渡す前の確認（人が必ず見る）

- [ ] 院名・地域・日付が正しい
- [ ] **悪口になっていない**。最初の一文は良い点から（例：口コミの評価が高い）
- [ ] 「改善ポイント3つ」が、その院だけの具体的な話になっている（数字・事実が入っている）
- [ ] 口コミの本文をそのまま引用していない（件数・返信数など数字だけ使う）
- [ ] 試算は「仮の数字・保証ではない」と書いてある。大きすぎる数字にしていない（追加の再来は月2〜5人程度が目安）
- [ ] 院の広告表現の問題（「治る」等）は**レポートに書かない**。気付いたら面談で口頭で、責める形にせず伝える
- [ ] 1ページに収まっている（はみ出したら note を短くする）
